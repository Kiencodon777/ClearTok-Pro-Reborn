# ClearTok v2.5 release gate

Merge the three stacked PRs in order: security, secure storage/performance, CI and release.
Pushes to main publish versioned RC prereleases only. Stable publication requires
the evidence below; do not publish the public update feed before approval.

## Required evidence per candidate commit

- Android device/model/OS and iPhone model/iOS version.
- Upgrade from v2.4.49: all five Hive boxes, settings and Supabase session preserved.
- Fresh install and retry after interrupted migration.
- QR/password login, external OAuth browser behavior, deep links and logout.
- Invalid certificate rejected with the TLS fixture in test/tls_fixture.py.
- Scan 10,000 records; switch hub/close route during a pending page.
- Unlike blank 200 readback, unfollow unverified response, CAPTCHA and 429 stop.
- On each platform, use a test account with a known liked video and followed
  account. Verify the manual action in the same TikTok WebView, then test the
  Studio action on a separate prepared item. Reload TikTok and check the actual
  like/follow state. Record the endpoint path, parameter **names**, body type,
  status, and POST count only. Never export a HAR, request values or profile IDs.
- Stop during handshake, POST, readback and rest. Check the sheet responds in
  one second, no subsequent item runs and late results cannot change history.
- Check Free operation 20/21 across all modes, including an ambiguous result.
  After a mobile upgrade, resume while signed in and refresh Devices. Verify
  the new version and restore a revoked installation with an available slot.
- Verified APK production signer fingerprint; IPA metadata and executable verified.
- Candidate observed for at least 48 hours with no crash or migration loss.

Record timestamps in UTC, candidate SHA, tester identity and result for each item.
Native checks cannot be inferred from mocked tests. PGlite serializes requests;
its competing enrollment regression is not a multi-session PostgreSQL load test.

## Stable release

After the checks, create v2.5.0 from the tested candidate commit, rebuild Android
and iOS together with APP_VERSION=2.5.0 and run the same packaging/signer gates.
Publish both installers and SHA-256 files in one release; then update the approved
public metadata feed. Keep split symbols private.

## Recovery

Secure boxes use *_secure_v2 and a Keychain/Keystore key. Never distribute v2.4.x
as a rollback after migration: it cannot read the encrypted boxes. Roll forward
with a v2.5.x fix. On key loss, preserve encrypted files and show Retry; do not
create a new empty database or delete user data automatically.
